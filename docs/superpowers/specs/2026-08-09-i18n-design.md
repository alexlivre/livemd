# i18n Design — LiveMD

**Date:** 2026-08-09
**Status:** Approved (with confirmation: non-supported OS languages fall back to English)

## Goal

Make LiveMD detect the OS language and adapt the whole UI (renderer + main process) to it, with a manual override dropdown in the titlebar. Supported languages: **pt-BR (`pt`)**, **en-US (`en`)**, **es (`es`)**. Any other OS language falls back to **English** (default).

## Requirements

1. UI language follows the OS locale by default (`app.getLocale()`).
2. Manual override: globe dropdown in the titlebar with `Automático`, Português, English, Español — persisted per user.
3. All user-facing strings are translated: renderer (buttons, status bar, empty state, recent menu, drop overlay, code-copy, tooltips, footer shortcuts) AND main process (open dialog title, file filters, error boxes).
4. TypeScript-enforced completeness: every language dictionary must have exactly the same keys.
5. OS languages outside pt/es (e.g. `fr`, `de`, `ja`) → `en`.
6. No new runtime dependencies.

## Architecture

### New file: `src/shared/i18n.ts`

Shared by main, preload contract and renderer. Contains:

- `type AppLanguage = 'pt' | 'en' | 'es'`
- `type LangSetting = 'auto' | AppLanguage` (what the user stores in localStorage)
- `const MESSAGES: Record<AppLanguage, Record<MsgKey, string>>` — `MsgKey` is derived from the `en` dictionary (`keyof`); TS errors if `pt`/`es` miss a key or have extras. `en` is the source of truth dictionary.
- `mapOsLocale(locale: string): AppLanguage` — `locale.startsWith('pt')` → `pt`; `startsWith('es')` → `es`; anything else → `en`.
- `t(lang: AppLanguage, key: MsgKey, params?: Record<string, string>): string` — dictionary lookup with minimal `{param}` interpolation (only needed for `Lendo: {file}`, `Atualizado: {file}`, `Fechar {name}`, error boxes).
- `LANG_OPTIONS` metadata for the dropdown: `[{ value: 'pt', label: 'Português' }, { value: 'en', label: 'English' }, { value: 'es', label: 'Español' }]`.

### Main process (`src/main/index.ts`)

- Module-level `currentLang: AppLanguage`, initialized from `mapOsLocale(app.getLocale())`.
- New IPC handlers:
  - `app:get-locale` → returns `app.getLocale()` (raw, renderer maps it) — actually simpler: returns the mapped `AppLanguage` derived from `app.getLocale()`. Decision: return the raw `app.getLocale()` string; mapping stays in shared code so both sides use `mapOsLocale`.
  - `app:set-language` → receives effective `AppLanguage` (from renderer after override resolution), stores it in `currentLang` (used for subsequent dialogs/errors). Note: the handler receives the language the renderer *wants*; main does not re-derive.
- `file:open-dialog`: title, `Markdown` and `Todos os arquivos` filter names → `t(currentLang, ...)`.
- `readMarkdownFile` throw `t(currentLang, 'notAFile')`; `file:read` guard throw `t(currentLang, 'markdownOnly')`; dialog error box title `t(currentLang, 'errorOpening')`.
- `IpcChannel` type in `src/shared/types.ts` gains `'app:get-locale' | 'app:set-language'`.

### Preload (`src/preload/index.ts`)

Extend `MdApi` (`src/shared/api.ts`) with:

- `getOsLocale(): Promise<string>` → `ipcRenderer.invoke('app:get-locale')`
- `setLanguage(lang: AppLanguage): Promise<void>` → `ipcRenderer.invoke('app:set-language', lang)`

### Renderer (`src/renderer/src/`)

New module `src/renderer/src/i18n.ts` (renderer-side singleton):

- `initI18n(): Promise<void>` — reads override from `localStorage['md-reader.lang']` (default `'auto'`), awaits `api.getOsLocale()`, computes effective language, stores it, and calls `api.setLanguage(effective)` once so main matches.
- `getEffectiveLang(): AppLanguage`, `getOverride(): LangSetting`, `setOverride(s: LangSetting)` (persists + recomputes + notifies).
- `t(key, params?)` curried helper bound to the effective language.
- On override change: notify a listener (main.ts re-applies UI).

`src/renderer/src/main.ts`:

- Replace all hardcoded pt-BR strings with `t(...)` — full inventory in "String inventory" below.
- `applyStaticStrings()` — updates static `index.html` texts/tooltips: titlebar subtitle (`app-subtitle`), `btn-recent`/`btn-theme`/`fab-open`/`btn-new` `title` attributes, footer `<kbd>` shortcut labels, drop overlay (`drop-title`, `drop-subtitle`), `document.documentElement.lang`.
- Language dropdown (`#lang-menu`, mirror of `#recent-menu` pattern): globe button in the titlebar actions, menu with 4 items — `Automático (<OS language label>)`, Português, English, Español — checkmark on the active item, click outside closes, `Esc` closes.
- After changing language: `applyStaticStrings()` + re-render current state (tabbar, content, status bar) + close menus.
- `renderEmpty()`, `renderContent()`, `renderRecentMenu()`, `setStatus()`, drop handlers, code-copy button, recent list — all use `t()`.

`src/renderer/index.html`:

- Add globe button + `#lang-menu` markup in the titlebar actions (before/after theme button, mirroring the recent-wrap pattern).
- Keep static texts but reference them via IDs where JS must set them (`app-subtitle`, shortcut labels, drop overlay texts). Initial content stays pt-BR (flash of default locale is acceptable; `initI18n` runs before first paint of dynamic content since `main.ts` module executes early).

### localStorage key

`md-reader.lang` — follows the frozen-key convention (`md-reader.theme`, `md-reader.recent`). Values: `'auto' | 'pt' | 'en' | 'es'`. Missing/invalid → `'auto'`. localStorage unavailable → `'auto'`.

## Data flow

1. Renderer boots → `initI18n()` → override from localStorage + `getOsLocale()` → effective language → `setLanguage(effective)` → `applyStaticStrings()`.
2. User opens file → main uses `currentLang` for dialog title/filters; errors via `t(currentLang, ...)`.
3. User picks a language in the dropdown → `setOverride(value)` → recompute effective → `setLanguage(effective)` → `applyStaticStrings()` + re-render state → persist `md-reader.lang`.
4. OS locale change while running → next launch picks it up (documented behavior; manual override covers immediate need).

## Edge cases

- OS in unsupported language (fr, de, ja, …) → `en` (default). Confirmed by user.
- Composite locales (`pt-PT`, `es-MX`, `en-GB`) → prefix match (`pt`, `es`, `en`).
- Invalid/missing `md-reader.lang` → `'auto'`.
- localStorage disabled → treated as `'auto'`.
- `app.getLocale()` may be empty → `mapOsLocale('')` → `en`.

## Verification

No test framework in this project. Verification = `npm run typecheck` (both tsconfigs), `npm run build`, and manual testing:

- Dev + packaged builds (`npm run pack` → `release/win-unpacked/LiveMD.exe`).
- Test all 3 languages via the dropdown; verify persistence across restarts.
- Verify `Automático` follows the Windows display language (Settings → Time & Language → Language), including a non-supported language → English.
- Verify main-process strings: open dialog title/filters, error boxes (open a folder as file, attempt non-md file).
- Verify drag & drop still works in packaged build (existing gotcha).

## Out of scope

- Pluralization library — simple `{n} file(s)` strings suffice (pt/es wording chosen to fit).
- Runtime OS-language change while the app is open (requires app restart — documented).
- Translating `exemplo.md` fixture or README content (README is already English; feature bullet added).
- Additional languages beyond pt/en/es.
